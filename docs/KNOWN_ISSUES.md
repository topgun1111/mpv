# KNOWN ISSUES

From the Session 0 audit (2026-11-17).

1. No PC EdgeTAM/SAM runtime exists (only the bank reference and the export script).
2. ~~`TrackGate` exists only in Kotlin.~~ Ported to `tracker/trackgate.py` and wired into `sam_track.py` (Session 5); thresholds are Android's and untuned on desk footage.
3. `requirements.txt` ships `onnxruntime-directml` only; CUDA is not available through it. Session 1 added the `providers` diagnostic and a separate-venv CUDA recipe (`DECISIONS.md`); the DirectML-vs-CUDA choice is still open until measured on your PC.
4. Real-clip validation on Windows (P23/V1) was never done, so current tracker quality on real footage is unknown.
5. Android code is uncompiled (`android/REMAINING.md`).
6. No desk/posture logic; seated handling is only the torso-length fallback in `parts.py`.
7. `target_fill` default is 0.30, not the 70% the roadmap asks for.
8. ~~No NVENC/NVDEC, no export validation, no stabilization.~~ Done in S13/S13b (`export.py`, `export_check.py`, `stabilize.py`). Still unverified: NVENC and NVDEC never ran on a real GPU; stabilization constants are untuned; `recorder/export.py` still drops the last 1-2 frames with audio (`-shortest`).
9. `handover.md` says Part tests were 374; the suite now has 466 tests (465 pass, 1 skipped). Doc is stale.
10. (Session 2) The five graphs have never been exported or timed. `export_sam2.py` itself was not run; the memory-graph export (RoPE rewrite) is the most likely part to fail.
11. (Session 2) `sam-bench --fp16` relies on `onnxconverter-common` (`keep_io_types=True`); untested on these graphs. fp16 can overflow or change the output: the report shows NaN/Inf and the difference to fp32.
12. (Session 2) VRAM is read with `nvidia-smi` (whole GPU, first GPU only) and only on CUDA rows; DirectML has no VRAM number.
13. (Session 4) `sam-track` has never run on the real graphs: the memory graph input/output contract (`mem_feats` [K, ...], `ptrs` [P, 256], `mem_feat` size, decoder-trk with label -1) is taken from `export_sam2.py` and Kotlin only.
14. (Session 4) No gate yet: every tracked frame is pushed to memory, including half-hidden ones (desk in front of the legs), and a mask that jumps onto the desk is not rejected. Session 5.
15. (Session 4) Tracked/lost uses the Android thresholds (conf 0.35, size ratio 0.25-4) untested on legs; the sampled frames are the only output (no interpolation), and a run cannot be resumed after Ctrl+C (only the partial file is kept).
16. (Session 8) Posture thresholds (`THIGH_*`, `REACH_*`, `ENTER_*`, `STAND_AT`/`SIT_AT`), hold times and the desk rule (`DESK_*`) are first guesses from body proportions; nothing was tuned on a real clip, and the posture geometry assumes a frontal camera.
17. (Session 8) The "legs hidden" cue is deliberately weak; a standing person whose knees stay undetected for 2-3 s can read as seated. A desk mask that is not much wider than the body region is not recognised as a desk (S7 clipping and the S5 gate are the only guards then). A rejected desk mask still sits in SAM's memory.
18. (Session 8) `sam-preview` has no posture (one frame); only `sam-track --posture` computes it. The mpv posture word was never rendered.
19. (Session 9) The state machine's thresholds (`MANUAL_LOST_S`, `OUT_MAX_S`, `CONFIRM_FRAMES`, `EDGE_MARGIN`, `EXIT_MOVE`, `EXIT_SHRINK`) are first guesses; never tuned on a real clip. Confirmation counts frames, so it assumes the default sampling (10/s).
20. (Session 9) A very fast exit (the box jumps to the edge and vanishes in one sample) has no motion history and reads TEMPORARILY_LOST unless `--posture` reports both legs gone. A static box resting on an edge that really leaves is only caught by that hint or by shrinking.
21. (Session 9) REACQUIRED means "tracked again for 3 frames" (since Session 10 with `--reid` also "the Re-ID verified it"; without it, not the same person check). MANUAL_RESELECT_REQUIRED is only a state and a label: nothing pauses `sam-track` or asks the user, and `reset()` has no UI caller. The mpv colours and the absence time were never rendered.
22. (Session 10) Re-ID is OSNet x0.25 with ImageNet pre-training (not Re-ID trained, see `models/MODELLER.txt`), applied to a seated person behind a desk (mostly upper body). Its similarity on that crop is untested; `reid_thres`/`reid_margin` are the live-mode defaults and `WEAK_BAND`, `GEO_*`, `HEIGHT_RANGE`, `ASPECT_RANGE` are first guesses.
23. (Session 10) With an empty gallery (no clean crop ever, e.g. the person box always touches the frame edge) or without `--pose` data, the check is skipped and S9 behaviour applies (the `re-ID:` line counts `doğrulanamadı`). Two people in similar clothes can also match; the margin only helps when both are in the frame.
24. (Session 10) A rejected stranger is only ignored by the state machine and the camera hold. SAM keeps tracking them and, if the TrackGate lets those frames through, they enter SAM's memory bank (Session 5 gate, not changed). A clip where the stranger stays a long time may need a manual reselect (`reset()` still has no UI caller).
25. (Session 10) Verification is offline only (it needs the frames after the return); live mode has no look-ahead and was not touched. The `reentry` rows are only for checked frames and are not aligned with `records`: use the `index` column.
26. (Session 11) All camera constants (2 s window, thresholds 0.24/0.12/0.10 log2, persistence 1.5/0.8/0 s, 0.25 log2/s) are first guesses, never tuned on a real clip. Persistence 0 in TRANSITION relies on S8 labelling the sit-down/stand-up; a late label means the first moment of a real size change is rate-limited but not delayed.
27. (Session 11) A foot excursion that stays beyond the threshold for longer than the persistence (for example a leg stretched out for several seconds that changes the region height by more than about 18% seated, 9% standing) does change the zoom, by design: it is indistinguishable from a real size change by geometry alone.
28. (Session 11) 70% is the region box height over the output height. A region already taller than that is left at 1x (no zoom below 1x); the pan clamp can also keep a region near the frame edge off centre. Occupancy in the `kamera:` line is measured before that pan clamp.
29. (Session 11) `sam-camera` / `--camera` write `<video>.views.json` and REPLACE an existing one (an `offline-view` result for the same video). The camera is not started from mpv's right-drag; there is no UI toggle yet. Not rendered on a real export.
30. (Session 11) The camera trusts the S9/S10 state: CANDIDATE and `other_person` frames are held, but if the state machine calls frames TRACKED while SAM sits on a stranger (see 24) the region follows the stranger and steers the camera.
31. (Session 12) Never run on the real graphs or a real clip. Re-prompting SAM with the forward BOX (the forward masks are not stored) may pick a different part than the original mask (for example thighs only); all thresholds (0.6, 0.5 IoU, 0.15 margin, 3-frame anchor, 150-frame window, spike 0.6) are first guesses.
32. (Session 12) Forward and backward are both SAM, so they share failure modes (the same desk or a look-alike can fool both). Agreement only shows consistency, which is why identity frames are never repaired. An `open` repair rests on the backward track's own `clean` flag alone.
33. (Session 12) Repaired frames do not feed the zoom and the posture/lower framing rows are not recomputed (no pose run); the camera only gains the pan and loses the hold/zoom-out there. `offline.py` smoothing and gap fill are not part of this path.
34. (Session 12) A Ctrl+C during `sam-refine` writes nothing (the refined file is written at the end); a crash inside one interval leaves only that interval unresolved and exits 1. Frame times of a window decode are matched within 0.6 sampling steps; a window that cannot be matched is `decode_failed`.
35. (Session 12) `sam-refine --camera` replaces `<video>.views.json` like `sam-camera`; `sam-track` has no `--refine` flag.
36. (Session 14) Validation found: the SAM pipeline cannot be started from mpv. `sam-track --rect` takes pixels from the CLI; right-drag in mpv starts the old `offline --select-rect`. DoD item 1 is therefore "failed" as stated. The flow is also five manual commands, and `sam-camera` / `sam-refine --camera` overwrite `<video>.views.json` (run the old-tracker baseline export first). Follow-up F2.
